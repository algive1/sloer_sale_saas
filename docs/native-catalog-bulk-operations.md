# 原生商品批量运营与发布边界

## 复用现有功能

原生 Dashboard 的 Channel 详情页已有“添加商品”批量向导，包含选择商品、默认发布设置、按商品填写价格/成本/库存、表格粘贴、确认、逐商品进度和手动重试。后台入口为 `/channels/{Channel全局ID}?action=bulk-publish`；部署到子目录时必须保留 Dashboard 配置中的前缀。

这条链路使用当前登录员工的 Saleor 权限和原生商品事实，不需要另建价格、库存或商品数据库。品牌运营页的 CSV 格式/原生核对仍然只读；不能把它或这条向导视作新商品/SKU CSV 导入功能。

| 范围         | 原生向导当前行为                                                                      |
| ------------ | ------------------------------------------------------------------------------------- |
| 商品选择     | 最多50个；原生管理员可以选择共享 Core 中的商品，需核对目标市场及共享影响              |
| 规格         | 每商品最多500个；每页读取100个，每批写入100个                                         |
| 价格/成本    | 同一商品填写的值应用于其所有规格；空价保留现有价格，不为未列出规格创造价格            |
| 现有价格展示 | 最多抽样100个规格；超过抽样上限不能视作完整现价核对                                   |
| 库存         | 对选择仓库的每个规格设绝对库存量；仓库可能供多个市场/品牌共享，影响不限于目标 Channel |
| 创建         | 可分配已有商品/规格；不是新商品、SKU、图片或重量的 CSV 创建/更新                      |

## 发布失败保护

提交时重新读取商品分配和完整规格列表。空列表、超过500且仍有下一页、重复规格、缺失或循环游标、部分 GraphQL 响应均拒绝；读取每页有15秒上限、整体45秒预算。

完整读取后，已有市场分配保留当前发布状态，新市场分配先设为未发布、不展示、不开放购买。随后写入规格价格/库存，只有所有批次的完整结果均无错误，才最后修改目标发布/购买开关。最终发布写入失败也报告失败。

**流程跨多个原生 mutation，不是事务。** `REJECT_FAILED_ROWS` 可能保存同批其他规格，先前批次也可能已完成；已有已发布商品在失败后仍保持原先状态。丢失回执时不能推定未写入。重试前应在原生商品页核对已保存的数据、仓库和其他人员的变动；没有自动重试、并发锁或跨批回滚。原生确认页中的重试由操作员主动点击。

## 本批验证

- 保留已有埋点和批量向导测试，增加500上限后的未完成分页、部分结果、重复身份、多页游标循环、规格加载失败、分批失败、缺结果行及最终发布失败回归。
- 真实生产 Dashboard 验收在一次性 CI 数据库中使用101个规格，沿两页读取。向第一批请求注入一个超币种精度值，由真实 Saleor 执行和拒绝该行，核对其他行可能已保存但商品仍未发布；手动重试后检查101个原生价格及最终发布状态。不是生产商户或真实支付验收。
- CI fixture 在全部 Sitemap/目录数量测试后才创建并发布，避免改变那些验收的目录。CI员工刷新令牌被掩码且仅用于此次环境；不能把它用于部署。

验收通过与合并状态见对应 PR。品牌后台入口、真实仓库库存写入、500+规格运营、SKU级CSV写入/创建、持久审计与未知结果恢复、生产Webhook缓存失效仍需分别完成。
