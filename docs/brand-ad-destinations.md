# 品牌广告投递与实时数据

## 配置与范围

品牌 ID、域名和市场仍以 `STOREFRONT_SITES_JSON` 为唯一来源。多品牌部署需要服务器私密变量 `ADS_SERVER_SITES_JSON`，每个品牌显式配置接收端；没有配置的品牌保持关闭，任何配置错误也不回退全局账户。

```json
[{"siteId":"fashion","ga4":{"id":"G-EXAMPLE","secret":"replace-with-private-api-secret"},"meta":{"id":"123456789","secret":"replace-with-private-token"},"tiktok":{"id":"PIXEL_EXAMPLE","secret":"replace-with-private-token"}}]
```

这个变量包含密钥，只存放于服务器的私密配置，不可放进 `NEXT_PUBLIC_*`、Git、工单或截图。重启 storefront 后生效。`/ops/analytics/destinations` 仅管理员可读，显示账户 ID、关闭/配置状态及最近40条投递结果，页面不返回密钥。多品牌需要可用的 `ANALYTICS_LIBSQL_*`；数据库无法占用事件时停止投递。

店铺请求同时校验 Host 和 Channel；已验签的退款入口根据订单 Channel 选账户。同意拒绝时不投递；广告供应商始终要求显式同意。GA4 的广告用户数据与广告个性化明确拒绝。未设置品牌注册表时保留原来的单站配置；没有数据库的旧单站没有持久去重与诊断记录。

默认不发送 IP。需要匹配 IP 时，先确认反向代理删除客户端同名头并写入真实值，再设置 `ANALYTICS_CLIENT_IP_HEADER` 为 `x-real-ip`、`cf-connecting-ip` 或 `x-storefront-client-ip`。该项依赖可信代理配置；供应商响应不能证明代理配置正确。

## 去重与诊断

事件发送前，以品牌、接收端和事件名/ID的摘要原子占用；每个接收端只尝试一次。超时、响应无法解析或完成状态无法保存时保留占用，避免重发已到达供应商的请求。后台显示：

| 结果 | 含义 | 处理 |
| --- | --- | --- |
| HTTP 已接收 | GA4 返回2xx；不证明事件已处理或进入报表 | 核对供应商验证工具与报表 |
| 供应商已确认接收 | Meta 返回 events_received 或 TikTok 返回 code=0 | 继续核对去重、归因和报表 |
| 失败 | HTTP错误或供应商拒绝 | 修正配置后，用新测试事件验收 |
| 结果不确定 / 待核对 | 网络、响应或状态保存不确定 | 在供应商侧核对；不自动重发原事件 |

持久记录不存客户邮箱、IP、URL、原始异常和密钥。`sending` 可能是进程中断，不要直接删除 claim 以重试。

## 实时看板与指标

`/ops/sites/{siteId}/realtime` 的8类查询均在聚合/排行前按可信品牌 Channel 过滤。品牌分析员只能读取授权品牌；API重新校验，查询参数不授予范围。自动刷新调用同一品牌API，失败保留上次有效数据并提示。全品牌入口仅管理员可读并标注汇总范围。品牌概况另展示 Saleor 的最近订单：逐市场读取、合并排序；任何市场失败或返回异品牌记录时整份列表不展示，不用部分结果冒充品牌全集；不将邮箱和地址传给该界面。

在线为最近5分钟有事件的会话；订单确认来自结账完成事件，可能存在未付款订单，不能视为真实支付收入。按币种展示金额，不直接汇总不同币种。收款、退款、税费、成本与财务对账仍以 Saleor 账本及支付服务的真实记录为准。

## 验收边界

此批补齐已有服务端事件的品牌账户、授权、去重、回执和运营诊断。多品牌浏览器全局像素继续关闭；没有完成品牌浏览器像素/Google Ads 全漏斗接入。单元测试模拟供应商响应，SQLite和浏览器回归使用独立CI数据，没有向真实广告账户发送请求。正式启用须配置真实账户并验证测试事件、币种、客户同意、浏览器/服务端去重及 GA4 会话关联。
