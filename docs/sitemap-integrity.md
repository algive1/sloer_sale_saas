# Sitemap 完整性与故障处理

`/sitemap.xml` 返回请求 Host 所属品牌的 sitemap index，索引只引用该品牌允许市场和语言的分片。分片列出公开 Saleor 商品、非空类目、公开集合及入口页。未知品牌 Host 返回 404；其他品牌的分片ID在当前Host也返回404。

## 本批修复

- 每页100条，按真实 `endCursor` 扫描分片边界。声明还有下一页却没有游标、空进展、重复游标、重复本地化地址或错误连接结构时，整次生成失败；不把已检查的一部分当完整结果。
- 查询选择严格完整性模式：即使 GraphQL 返回部分 `data`，只要同时有 `errors`，也不生成成功地图。其他原有 GraphQL 调用的默认行为保持兼容。
- 单页请求最多8秒，每种资源每个市场/语言最多60秒、500页。查询不自动重试；超限、上游故障或本地化地址冲突必须修复后重新访问，不能通过延长循环掩盖。
- 按语言×市场×资源类型×页段分片，单片最多10个游标页/1000个地址；索引和每片分别检查50,000地址及50,000,000字节XML上限，并检查实际UTF-8输出大小。不同语言市场不会共用一个全局商品偏移。

## 分片与缓存

- `/sitemap.xml` → `/sitemaps/{语言市场编码}-{资源}-{页段}.xml`。首页/商品入口也单独成片。目录增大后索引引用多个分片，根文档不会堆积全部商品URL。
- 扫描仅保存起始游标、页数及条数；用摘要检测跨页本地化地址重复，不保留完整商品节点或全目录URL矩阵。分片请求只读取自己的最多1000条资料；如果页数/条数已经变化，返回503，避免成功输出过期的不完整分片。
- 游标页和分片清单使用原有`catalog` Cache Components缓存及`products/categories/collections`失效标签。HTTP保持必须重新验证，按Host区分响应；发生上游故障时503/no-store/Retry-After，不自动重试或暴露原生错误资料。
- 使用自定义index/分片Route Handler，在任何目录I/O之前校验运行时Host与品牌矩阵。Next内建generateSitemaps会在构建期枚举ID、在分片请求中先调用枚举器，不能直接满足这里的运行时Host前置边界；这仍保留索引、稳定维度、游标分段和缓存的项目架构要求。
- 当前仍有每资源/市场/语言500页和60秒预算，超限不会截断。更大或更新特别频繁的目录须另行建设后台快照/对象存储导出；原生游标与缓存没有跨多个HTTP请求的数据库快照保证。分片功能不能代替百万级目录与生产峰值验收。

## 验证与运营

- 本地分页测试覆盖多页、游标循环/缺失、空进展、身份碰撞、页数/时间/字节上限，以及部分GraphQL响应拒绝；分片测试检查清单仅保存游标范围、语言/市场范围、翻译、空类目过滤和分片变化拒绝。
- 实际Next HTTP开发fixture验证超过1000商品的多分片发现、两品牌语言完整数和未知/外品牌Host404；开发fixture不替代真实Saleor验收。通过情况以本批PR最后提交为准。
- 原生CI沿index访问每片，以Saleor`products.totalCount`独立核对每个品牌语言的全部XML商品数，继续检查生产构建/品牌隔离/本地化。不能只核对index链接数量或单一片段。
- 正式上线后访问各品牌地图确认HTTP成功、地址只属于本品牌，查看服务器故障记录和 Search Console 覆盖情况。不能只以根首页200推断SEO发现正常。
- 暂停 `seo-merchant` 扩展不会停止核心 Sitemap；Google Merchant 账户、政策事实、死链/重定向中心仍需单独完成。

协议上限参考：[Google 创建和提交 Sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)。
