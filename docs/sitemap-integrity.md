# Sitemap 完整性与故障处理

`/sitemap.xml` 只列出请求 Host 所属品牌、允许市场和语言的公开 Saleor 商品、非空类目和公开集合。未知品牌 Host 返回 404，不返回成功的空地图。

## 本批修复

- 每页100条，按真实 `endCursor` 收集全部页面。声明还有下一页却没有游标、空进展、重复游标、重复本地化地址或错误连接结构时，整次生成失败；不把已收集的一部分当完整结果。
- 查询选择严格完整性模式：即使 GraphQL 返回部分 `data`，只要同时有 `errors`，也不生成成功地图。其他原有 GraphQL 调用的默认行为保持兼容。
- 单页请求最多8秒，每种资源每个市场/语言最多60秒、500页。查询不自动重试；超限、上游故障或本地化地址冲突必须修复后重新访问，不能通过延长循环掩盖。
- 合并所有语言/市场后的地图检查50,000条地址及保守的50,000,000字节XML上限。超过上限拒绝生成，不截断。字节检查只适用于当前 URL/changefreq/priority 字段；以后添加图片/视频等XML必须同步更新大小估算。

这些是故障保护，**尚未实现大目录的分片和 sitemap index**。预计接近上限的品牌须先完成分片功能再扩充目录，不能把失败保护当大规模目录已支持。

## 验证与运营

- 本地分页测试覆盖多页、游标循环/缺失、空进展、身份碰撞、页数/时间/字节上限，以及部分 GraphQL 响应拒绝；源查询测试检查品牌市场、翻译地址和空类目过滤。
- 实际 Next HTTP 测试用101个商品的开发 fixture 触发第二页，验证两品牌语言的完整商品数和未知 Host 404。这是开发验证，不替代真实 Saleor 验收。
- 原生 CI 使用 Saleor `products.totalCount` 独立核对每个品牌语言的 XML 商品地址数，保留已有生产构建/品牌隔离/本地化测试。通过情况以本批 PR 的最后提交为准。
- 正式上线后访问各品牌地图确认HTTP成功、地址只属于本品牌，查看服务器故障记录和 Search Console 覆盖情况。不能只以根首页200推断SEO发现正常。
- 暂停 `seo-merchant` 扩展不会停止核心 Sitemap；Google Merchant 账户、政策事实、死链/重定向中心仍需单独完成。

协议上限参考：[Google 创建和提交 Sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)。
